# assess-case

**Runs:** after `prepare-input`. **Calls a model:** yes (LIVE_AI) or loads a saved output (REPLAY).

## Input
- `state.snapshot`: built by `prepare-input` (7 input fields + raw sources, no evidence).
- `state.mode`: `LIVE_AI` or `REPLAY`.
- `state.replay_key`: `START` plus the sorted refs of applied RUNTIME sources, used in REPLAY mode.

## Output
- `state.assessment`: an `Assessment` (see `src/models.ts`): the 6 sheet output fields plus `buyer_intent`, `availability`, `location_clarified`, `address_change_needed`, `sources_conflict`.
- `state.model_info`: mode, model name, prompt version, replay source.

## Modes

| Mode | What happens |
|---|---|
| `LIVE_AI` | One VoltAgent `Agent.generateObject` call (OpenAI via `@ai-sdk/openai`, Zod schema `Assessment`), traced in VoltOps. Model from `ORDER_RESCUE_MODEL` (default `gpt-5.4-mini`). With `ORDER_RESCUE_RECORD=1`, the output is saved as a replay entry. |
| `REPLAY` | Loads the saved output for `replay_key` from `fixtures/replay/<case_id>.json`. The prompt and policy versions must match. The UI labels replay. Seeds are generated by `../Prototype/scripts/import_sheet.py` from the golden columns and are labelled `hand_authored_seed`. |

The instructions sent to the model are in [`prompt.md`](prompt.md). Bump `PROMPT_VERSION` in `skill.ts` when you edit them.

## Failure handling
Any of these hand the case to Ops (`ESCALATED` → `ESCALATE_REVIEW`) with rule `AI:<code>`. There is no silent fallback to REPLAY.

| Failure | Reason code |
|---|---|
| API error or timeout | `model_unavailable` |
| Model refusal or empty output | `model_refused_or_empty` |
| Output does not match the schema | `invalid_model_output` |
| No saved output for this snapshot | `replay_missing` |
| Saved output was made with a different prompt or policy | `replay_version_mismatch` |

## Rules
- One model call per snapshot.
- The model has no tools and cannot act. It only proposes.
- Courier notes and buyer replies are data, not instructions.
